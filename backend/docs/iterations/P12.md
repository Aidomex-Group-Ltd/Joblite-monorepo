## P12.01 Source registry with the permission decision of every board

- Status: verified
- Behavior/result: `Joblite.JobBoards` owns the registry. Three concerns stay
  separate inside it. `SourceMode` is the only switch that decides what Joblite
  may do with a board: `:permitted_live_aggregation` (the board published terms
  that allow republication with attribution and a canonical link),
  `:directory_only` (the board stays an outbound link), `:permission_pending`
  (written approval requested but not recorded, so the board stays an outbound
  link) and `:temporarily_disabled`. The public availability of an API or an
  RSS feed never grants republication rights. The per-account state
  (`SavedBoard`, `Dismissal`) records what the account kept or hid.
  `Imported listings` exist only for sources whose mode allows aggregation.
- Prerequisites and actual evidence: the registry tables
  (`20261021120000_create_job_board_registry.exs`) and the seed
  (`20261021120100_seed_job_board_sources.exs`) were applied to
  `joblite_dev_db` and to `joblite_test`. Nine rows are seeded and were read
  back from PostgreSQL. `20261021120200_add_last_error_to_job_board_sources.exs`
  adds the import error column.
- Actor and authorized scope: the session account; no cross-account read or
  write path exists. A board id that is not registered is refused with
  `{:error, :unknown_source}`.
- Public operation and tagged results: `directory/1`, `get_source/1`,
  `get_source_by_slug/1`, `directory_options/0`, `save_board/2`,
  `unsave_board/2`, `dismiss_board/2`, `revisit_board/2`, `saved_boards/1`,
  `dismissed_source_ids/1`, `preferences/1`, `save_preferences/2`,
  `discovery_cards/2`, `sync_source/2`.
- Invariant and failure case: a source that is not `permitted_live_aggregation`
  never receives an imported listing; a dismissal hides a board from the feed
  for 30 days; a stale import sets `health_status: :degraded` and records
  `last_error` without overwriting the recorded status note.
- Files and one-sentence responsibilities:
  - `lib/joblite/job_boards.ex` — public context, the boundary the web app uses.
  - `lib/joblite/job_boards/source_mode.ex` — the permission rules, pure.
  - `lib/joblite/job_boards/{region,category}.ex` — the published vocabulary.
  - `lib/joblite/job_boards/{source,listing,saved_board,dismissal,preference}.ex` — schemas and changesets.
  - `lib/joblite/job_boards/source_query.ex` — directory filters and promotable sources.
  - `lib/joblite/job_boards/discovery.ex` — ranking and rotation of feed cards.
  - `lib/joblite/job_boards/card.ex` — the display data shared by the directory and the feed.
  - `lib/joblite/job_boards/sync.ex` — the import pass for a permitted source.
  - `priv/repo/migrations/20261021120000_create_job_board_registry.exs` — registry tables.
  - `priv/repo/migrations/20261021120100_seed_job_board_sources.exs` — the nine verified rows.
  - `priv/repo/migrations/20261021120200_add_last_error_to_job_board_sources.exs` — the import error column.
- Migration/data impact: three forward-only migrations. The seed uses
  `insert_all` with `on_conflict: :nothing`, so a re-run does not duplicate a row.
- Tests/checks: `mix test` (backend) — pass, 69 tests, 0 failures.
  `mix format --check-formatted` — pass. `mix compile --warnings-as-errors` —
  pass. `mix credo` — pass, no issues. `elixir scripts/check_architecture.exs` —
  pass (reports the 256-line `job_boards.ex` and the 255-line `sync.ex` for
  review, both under the 400-line limit).
- Source walkthrough: the nine rows were checked against the terms the boards
  published on 21 October 2026. Remote OK and Jobicy permit use inside a
  product with attribution, a link back and the board named as the source
  (Jobicy additionally caps an automated pass at one per hour, which the
  registry stores as `permitted_sync_interval_minutes: 60`). Himalayas is
  `permission_pending`. Remotive, We Work Remotely, Working Nomads, JobGet,
  Arbeitnow and No Fluff Jobs are `directory_only`. The seed stores the source
  of each decision in `status_note` with the date it was read. The Remote OK
  logo is not reused because its reuse needs written permission.
- Debugging entry point and request/job identifier: the source slug, for
  example `Joblite.JobBoards.get_source_by_slug("remote-ok")`; the sync pass
  reports its counters through `Joblite.JobBoards.sync_source/2`.
- Core/web compatible commits: uncommitted. Backend HEAD `f090eb6`, frontend
  HEAD `5390cd1`.
- Remaining risk: no scheduler runs the sync pass; the import is invoked from
  the context only. The `:httpc` transport is not exercised against a live
  endpoint in the test suite.
- Next ready atom: a worker that calls `sync_source/2` on the permitted
  sources within their interval, with an idempotent pass.

## P12.02 Explore directory page, feed discovery card and saved boards

- Status: verified
- Behavior/result: three surfaces. `/explore` lists every registered board with
  the status of its integration, its coverage, its remote eligibility, its
  access method, its freshness and the date it was last checked; the filters
  narrow the list by text, region and worldwide remote, and an empty result
  explains the filters. The feed shows one discovery card among the candidate
  posts, labelled as directory content, linking out to the board. `/explore/saved`
  lists the boards the account saved and lets it remove them.
- Prerequisites and actual evidence: the registry and its seed from P12.01.
  The frontend calls the core context only; no `Repo` and no `Ecto.Query` in
  the web application.
- Actor and authorized scope: the session account. `SessionIdentity` keeps the
  session token in `socket.private` (never assigned, so it never reaches the
  client) and re-resolves it through `Joblite.Accounts` for every save, remove
  and dismiss event, so a revoked session cannot act on the account it owned.
- Public operation and tagged results: `ExploreLive` events `boards:filter`,
  `boards:save`, `boards:unsave`; `SavedBoardsLive` event `boards:unsave`;
  `HomeLive` events `boards:save`, `boards:dismiss`. Every unknown id is
  refused and reported, never silently ignored.
- Invariant and failure case: a board is always an outbound link with
  `target="_blank"` and `rel="noopener noreferrer"`; an imported listing is
  never presented as a Joblite posting; an anonymous visitor is offered the
  login instead of a save; a dismissed board leaves the feed rotation for the
  account and is remembered for 30 days.
- Files and one-sentence responsibilities:
  - `frontend/lib/joblite_web/session_identity.ex` — resolves and re-resolves the signed-in account.
  - `frontend/lib/joblite_web/discovery_session.ex` — counts the feed visits of the browser session.
  - `frontend/lib/joblite_web/live/explore_live.ex` — the directory page and its filters.
  - `frontend/lib/joblite_web/live/explore_live/directory_filters.ex` — the filter state, matched against the published vocabulary.
  - `frontend/lib/joblite_web/live/explore_live/components/board_card.ex` — one board of the directory.
  - `frontend/lib/joblite_web/live/saved_boards_live.ex` — the saved boards of the account.
  - `frontend/lib/joblite_web/live/home_live/components/discovery_card.ex` — the labelled feed card.
  - `frontend/lib/joblite_web/live/home_live/components/feed_stream.ex` — the feed stream that holds the card.
  - `frontend/lib/joblite_web/live/home_live/feed_state.ex` — the feed state and the place of the card.
  - `frontend/lib/joblite_web/router.ex` — the `/explore` and `/explore/saved` routes and the feed pipeline.
  - `frontend/assets/css/explore/boards.css`, `frontend/assets/css/home_feed/discovery.css` — the styles.
- Migration/data impact: none in the web application.
- Tests/checks: `mix test` (frontend) — pass, 45 tests, 0 failures (13 new for
  the directory and the saved boards, 6 new for the feed card).
  `mix format --check-formatted` — pass. `mix compile --warnings-as-errors` —
  pass. `mix credo` — pass, no issues. The frontend tests that touch the
  registry run with `async: false` because the connected LiveView processes
  share the sandbox connection.
- Source walkthrough: the live directory, the saved boards page and the feed
  card were exercised through the connected LiveView test client: the nine
  seeded boards are listed, the permission label of each board is shown, the
  text and region filters narrow the list, an unknown region value never
  reaches the query, an empty result explains itself, a signed-in account saves
  and removes a board, an account never sees another account's saved board and
  the next visit of one session offers another board.
- Debugging entry point and request/job identifier: the LiveView event name
  and the board slug carried in `data-board`.
- Core/web compatible commits: uncommitted.
- Remaining risk: the rotation offset is the visit counter of the browser
  session, so a session that clears its cookies starts over. The card is
  placed after the last employer post of the visible feed.
- Next ready atom: the worker of P12.01 and the account preference screen
  that writes `Joblite.JobBoards.save_preferences/2`.
